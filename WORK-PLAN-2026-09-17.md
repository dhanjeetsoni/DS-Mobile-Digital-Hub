## Part 0 — Repo ↔ Production drift reconcile (SABSE PEHLE)

**Kyun:** ZIP production se **peeche** hai. Agar isi ZIP se kaam aage badhaya to
live cheezein galti se overwrite/duplicate ho jayengi (yeh galti is project mein
pehle 3 baar ho chuki hai — `upsert_product_catalog` ka duplicate overload wala case).

**Evidence (aaj measure kiya):**
- Live par **28 migrations** hain jinki SQL file repo mein **hai hi nahi** — jaise
  `phase8_typo_tolerant_screen_size_search`, `phase8_fuzzy_screen_size_cache_lookup`,
  `phase9_lock_down_public_execute_properly`, `phase10_category_quote_cache`,
  `phase11_lock_down_detect_ai_provider_from_anon`, `phase6_staff_access_window_and_sections`,
  `phase5_crash_reports`, `phase6_price_history_and_force_logout` waghera.
- Repo ki **19 migration files** round-number timestamps (`...060000`, `...130000`) ke saath
  hain jo live par alag timestamp se apply ho chuki hain — yaani duplicate copies.
- Live par **2 edge functions** hain jo repo mein nahi: `debug-gemini-probe`, `ai-product-search`.

**Kaam:**
1. Har missing migration ka live definition nikaal ke repo mein file banana (sahi version prefix ke saath).
2. Duplicate/round-timestamp files ko `migrations_legacy_pre_v2/` mein move karna (delete nahi).
3. Dono missing edge functions ka live source pull karke repo mein commit karna.
4. `debug-gemini-probe` — decide: production se hatana hai ya rakhna (debug function live par pada hai).

**Verify:** local file list vs `list_migrations` ka output 1:1 match ho jaye.

## Part 1 — "Naye features" ka audit + cloud wiring (asli kaam)

**Finding:** ZIP mein **12+ naye feature components** hain jo *kisi bhi* plan doc
(`PROJECT_PLAN.md` / Master Plan / Completed Points) mein likhe hi nahi hain:

`SmartRestockPredictorView`, `StaffIncentiveTrackerView`, `DeadStockHeatmapView`,
`LoyaltyRewardsView`, `MonthlyReviewView`, `PersonalDrawingsView`,
`OfflineSyncCenterView`, `SecurityAuditLogView`, `StockAuditScannerView`,
`ImeiWarrantyLookupView`, `ExportClearInvoicesView`, `QuickServiceModal`,
`StaffAttendanceView`, `CounterCalculatorModal`.

Achhi baat: sab `App.tsx` mein import + route ho chuke hain, aur Sidebar ke
50 nav keys aur App ke 50 route cases **poori tarah match karte hain** (koi orphan page nahi).

### 🔴 1A — Naye features ka data cloud tak pahunch hi nahi raha (CRITICAL)
Live `store_state` JSON mein **32 keys** hain. In naye features ki keys
**maujood hi nahi hain**: `staffIncentives`, `securityAlerts`, `staffAttendance`,
`purchaseOrders`, `poSeq`.
→ Matlab incentive records, security alerts, attendance, purchase orders abhi
**sirf us ek device par** hain. Doosre device par kuch nahi dikhega, aur device
reset hone par data gaya.

**Kaam:** in collections ka save/load path verify karna, default init, aur
multi-device sync confirm karna (do session banakar live test).

### 🔴 1B — Staff projection naye features ke liye update hi nahi hui (SECURITY)
Live `project_staff_state()` sirf 10 purani collections blank karta hai
(purchases, suppliers, supplierPayments, expenses, secondHandKYCs, imeiRegistry,
gallaClosings, moneyLenders, lenderTransactions + products/sales/batches ki cost fields).

Naye features isse **chhoot gaye**:
- `purchaseOrders` → `RestockPurchaseOrderItem` mein **`purchasePrice` aur `totalCost`** hai
  → **staff ko purchase cost dikh jayega** — exactly wahi leak jise rokne ke liye yeh
  poora projection system banaya gaya tha.
- `staffIncentives` → ek staff ko doosre staff ki commission/incentive dikh jayegi.
- `securityAlerts` → staff ko apne hi upar ke security alerts dikh jayenge.
- `lapuWallets`, `extraIncome` → owner ka paisa data staff ko dikhega.

Saath hi `save_store_state_for_user()` in keys ko merge-protect nahi karta →
purana/offline staff device inko **blank bhi kar sakta hai**.

**Kaam:** naya migration — `project_staff_state()` + `save_store_state_for_user()`
dono mein yeh keys add karna (blank + merge/restore), phir live par actual staff
role se query karke prove karna ki cost field ab nahi aa raha.

### 1C — Har naye feature ka functional pass
Ek-ek karke: reachable hai?, empty state theek?, mobile width par theek?,

`onApplyReconciliation`, `onRedeemPoints`) sach mein persist hote hain?

### 1D — Documentation

## Part 2 — Security hardening (Phase 9 adhoora hai)

Live Security Advisor aaj chalaya:
- **30 `SECURITY DEFINER` functions abhi bhi `anon` (bina login) se callable hain** —
  including `save_store_state_for_user`, `load_store_state_for_user`,
  `upsert_product_catalog`, `set_product_photos`, `reserve_invoice_number`,
  `publish_app_version`, `set_app_version_live`, `admin_force_logout_profile`,
  `get_customer_purchase_history`, `get_product_price_history`, `get_staff_performance`.
  Phase 9 ne sirf ek subset lock kiya tha, baaki chhoot gaye.
- 8 **trigger functions** (`notify_low_stock`, `log_table_audit`, `handle_new_user`,
  `sync_products_staff_view`, …) REST API se callable hain — inhe kisi client se
  callable hona hi nahi chahiye.
- `detect_ai_provider` ka `search_path` mutable hai (WARN).
- `pg_trgm` extension `public` schema mein hai (WARN).
- **Leaked-password protection abhi bhi OFF** — yeh sirf aap Dashboard se on kar sakte ho.

**Kaam:** ek migration — `REVOKE EXECUTE ... FROM PUBLIC` + explicit
`GRANT TO authenticated, service_role` (sirf `REVOKE FROM anon` kaam nahi karta,
yeh is project mein pehle prove ho chuka hai), `handle_new_user` ke liye
`supabase_auth_admin` grant zaroor rakhna (warna naya signup toot jayega),
phir har function ke liye `has_function_privilege()` se pehle-baad verify karna.

## Har part ka fixed tareeka (process)

1. **Investigate** — code + live DB dono padhna, purane ✅ par bharosa nahi.
2. **Change** — chhota, focused change.

## Ek blocker — GitHub push

Mere paas abhi GitHub ka access **nahi** hai (bina token API rate-limit par block ho
raha hai). Do options:
- **(a)** Ek short-expiry, sirf is repo ka fine-grained token dena — scope: Contents
  (read/write) + Workflows. Kaam khatam hote hi revoke kar dena.
- **(b)** Token nahi dena — main har part ke baad updated ZIP + exact commit message
  dunga, aap khud push kar doge.

Supabase access mere paas **hai** — migration apply + live verify main khud kar sakta hoon.
